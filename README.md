# MCP File Assistant

Учебный проект к уроку 3.2 «Использование MCP-серверов».

## Цель проекта

Изучить взаимодействие Codex с локальной файловой системой через Model Context Protocol (MCP), проверить доступные файловые операции и сравнить выполнение одной и той же задачи через Filesystem MCP и встроенные средства Codex.

## Что такое MCP

Model Context Protocol (MCP) — открытый протокол, через который модель получает стандартизированный доступ к внешним инструментам и контексту. MCP-сервер публикует набор инструментов с описанными параметрами, а MCP-клиент, например Codex, вызывает их для чтения данных или выполнения разрешённых действий.

В этом проекте MCP используется для ограниченной работы с локальной файловой системой: получения списка файлов, поиска, чтения метаданных, создания и редактирования файлов. Доступ сервера ограничивается каталогами, переданными при запуске.

## Подключённый MCP-сервер

В экспериментах использован пакет `@modelcontextprotocol/server-filesystem`, подключённый в Codex как сервер `filesystem`.

Фактически были доступны и использованы инструменты с префиксом `mcp__filesystem__`, в частности:

- `mcp__filesystem__list_directory`;
- `mcp__filesystem__search_files`;
- `mcp__filesystem__get_file_info`;
- `mcp__filesystem__create_directory`;
- `mcp__filesystem__write_file`;
- `mcp__filesystem__read_text_file`;
- `mcp__filesystem__edit_file`;
- `mcp__filesystem__read_multiple_files`;
- `mcp__filesystem__read_media_file`.

## Подключение Filesystem MCP к Codex на Windows

1. Установить Node.js и убедиться, что команда `npx` доступна в `PATH`.
2. Открыть настройки MCP в Codex либо добавить секцию сервера в пользовательский `~/.codex/config.toml` или проектный `.codex/config.toml` для доверенного проекта.
3. Использовать безопасный шаблон из `submission/mcp_config_example.toml` и заменить только пример пути на локальный путь к проекту.
4. Перезапустить Codex после изменения конфигурации.
5. Проверить подключение командой `codex mcp list` или через `/mcp` в интерфейсе Codex.

Минимальный пример:

```toml
[mcp_servers.filesystem]
command = "npx.cmd"
args = ["-y", "@modelcontextprotocol/server-filesystem", "C:\\path\\to\\MCP_File_Assistant"]
```

В конфигурации следует указывать только те каталоги, к которым серверу действительно нужен доступ. Токены и ключи API для локального Filesystem MCP не требуются.

Официальная документация Codex подтверждает, что MCP-серверы можно настраивать через `config.toml`, а для локального STDIO-сервера используются поля `command` и `args`: <https://learn.chatgpt.com/docs/extend/mcp>.

## Проведённые эксперименты

### Эксперимент № 1. Поиск договоров и формирование отчёта

Через Filesystem MCP был получен список десяти тестовых документов. Среди них найдены четыре файла, имена которых начинаются с `contract_`. Для каждого файла получен фактический размер и создан отчёт `reports/contracts_report.csv`.

| № | Название файла | Размер (байт) |
|---:|---|---:|
| 1 | `contract_lease_silver_forest.docx` | 37 632 |
| 2 | `contract_services_amber_bridge.docx` | 37 663 |
| 3 | `contract_supply_northern_star.docx` | 37 643 |
| 4 | `contract_support_blue_horizon.docx` | 37 638 |

Подтверждённые инструменты:

- `mcp__filesystem__list_directory` — получение исходного списка из десяти файлов;
- `mcp__filesystem__search_files` — поиск файлов `contract_*`;
- `mcp__filesystem__get_file_info` — получение размера каждого договора;
- `mcp__filesystem__create_directory` — подготовка каталога `reports`;
- `mcp__filesystem__write_file` — сохранение CSV в UTF-8 с BOM и разделителем `;`.

### Эксперимент № 2. Создание, чтение и редактирование TXT

Через MCP создан файл `documents/mcp_experiment.txt` с тремя строками:

```text
Договор № 101 от 01.10.2026
Контрагент: ООО Альфа
Сумма: 100000 руб.
```

После первого чтения инструмент `mcp__filesystem__edit_file` заменил только последнюю строку. Контрольное чтение показало:

```text
Договор № 101 от 01.10.2026
Контрагент: ООО Альфа
Сумма: 150000 руб.
```

Первые две строки остались без изменений. Подтверждённые инструменты:

- `mcp__filesystem__write_file`;
- `mcp__filesystem__read_text_file` — два чтения;
- `mcp__filesystem__edit_file`.

### Эксперимент № 3. Создание CSV с MCP и без MCP

Одинаковая задача формирования отчёта по четырём договорам выполнена двумя способами.

Без MCP использованы:

- `exec_command` с PowerShell — поиск файлов, получение фактических размеров и проверка результата;
- `apply_patch` — создание `reports/contracts_without_mcp.csv`.

Через Filesystem MCP использованы:

- `mcp__filesystem__search_files`;
- `mcp__filesystem__get_file_info`;
- `mcp__filesystem__write_file`;
- `mcp__filesystem__read_multiple_files`;
- `mcp__filesystem__read_media_file`.

Результатом стали файлы `reports/contracts_without_mcp.csv` и `reports/contracts_with_mcp.csv`.

## Сравнение выполнения с MCP и без MCP

Оба способа сформировали одинаковые табличные данные: совпадают заголовки, порядок четырёх файлов и размеры в байтах. Оба CSV используют разделитель `;` и содержат UTF-8 BOM.

Побайтово файлы различаются:

- `contracts_without_mcp.csv` — 231 байт;
- `contracts_with_mcp.csv` — 236 байт.

Разница связана с техническим оформлением окончаний строк: в первом файле используются `LF`, во втором — `CRLF` и завершающий перенос строки. При открытии как таблицы это не меняет данные.

С точки зрения процесса Filesystem MCP даёт явные специализированные операции и ограничивает доступ заранее разрешённым каталогом. Без MCP та же задача была выполнена обычными инструментами Codex и PowerShell. Вывод о скорости не делается: специального сопоставимого замера времени не проводилось.

## Безопасность

- В материалы не включены токены, пароли, API-ключи и личный файл настроек Codex.
- `submission/mcp_config_example.toml` содержит только обезличенный пример пути.
- `.gitignore` исключает локальные настройки, секреты, vault-файлы, временные каталоги, журналы и зависимости, но не исключает учебные DOCX, TXT, CSV и безопасный пример конфигурации.
- Исходные DOCX не изменялись.
- Все десять учебных DOCX включаются в репозиторий как материалы экспериментов.

## Итоговые выводы

Filesystem MCP успешно предоставил Codex контролируемые инструменты для поиска, получения метаданных, чтения, записи и точечного редактирования файлов. Три эксперимента подтвердили работоспособность сервера и воспроизводимость результата: данные CSV, созданных разными способами, совпали. Техническое различие окончаний строк не влияет на содержание таблиц. Утверждать преимущество одного подхода по скорости нельзя без отдельного измерения.
